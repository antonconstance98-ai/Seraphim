    **`callWithRetry(fn, maxRetries)` — internal helper (Claude's discretion):**
    - Exponential backoff with jitter: base delay `Math.min(1000 * Math.pow(2, attempt), 8000)`, jitter `Math.random() * 500`.
    - Default `maxRetries = 3`.
    - Catches any error, waits, retries. Throws last error after all retries exhausted.

    **`runMinimax(prompt, opts)` — per D-01 through D-05:**
    - Parameters: `prompt` (string), `opts` (optional object)
    - `opts.model` defaults to `'MiniMax-M2.7'`
    - `opts.maxTokens` defaults to `2000` (per D-04 — verbosity control)
    - `opts.timeoutMs` defaults to `90000` (90s — per Pitfall 2, pre-answer latency up to ~55s)
    - `opts.temperature` defaults to `0.01` (per D-03 — MiniMax rejects exactly 0)
    - `opts.systemPrompt` optional string — if provided, prepend as `{ role: 'system', content: systemPrompt }` before the user message
    - Check `process.env.MINIMAX_API_KEY` — if not set, return `{ success: false, text: '', tokens: null, cost: 0, error: 'MINIMAX_API_KEY is not set' }`
    - Lazy-require OpenAI SDK: `try { OpenAI = require('openai').OpenAI } catch { OpenAI = require(OPENAI_GLOBAL_PATH).OpenAI }`
    - Create client: `new OpenAI({ baseURL: MINIMAX_BASE_URL, apiKey })`
    - Use AbortController with `setTimeout(() => controller.abort(), timeoutMs)` — same pattern as `runGpt54MiniApi`
    - Wrap the API call in `callWithRetry` for transient error resilience

    **`isCodexRateLimited(codexResult)` — per D-15:**
    - Input: result object from `runCodexExec`
    - Returns `true` if any of these conditions match:
      1. `codexResult.rateLimitPct !== null && codexResult.rateLimitPct >= 95`
      2. `codexResult.error` contains (case-insensitive): `'rate limit'`, `'quota'`, `'usage limit'`
      3. `codexResult.output` contains `'"status":429'` (HTTP 429 in JSONL)
      4. `codexResult.error` contains `'timed out'` AND (`!codexResult.output` or `codexResult.output.trim() === ''`)
    - Returns `false` otherwise, including if `codexResult` is null/undefined

    **`runWithFallback(prompt, opts)` — per D-06, D-14 through D-17:**
    - Parameters: same as `runMinimax` plus `opts.taskCategory` (`'execution'` | `'review'`, default `'review'`)
    - Step 1: Try Codex CLI via `const { runCodexExec } = require(CODEX_EXEC_PATH); const codexResult = await runCodexExec(prompt, opts);`
    - If `codexResult.success`: return `{ success: true, text: codexResult.output, tokens: codexResult.tokens, cost: 0, source: 'codex-cli', error: null }`
    - Step 2: Check if rate-limited via `isCodexRateLimited(codexResult)`
    - If rate-limited (per D-16): call `runMinimax(prompt, opts)`
      - If MiniMax succeeds: return `{ ...minimaxResult, source: 'api-fallback' }`
      - If MiniMax fails: fall through to Step 3
    - If Codex failed for non-rate-limit reason: return `{ success: false, text: '', tokens: null, cost: 0, source: 'codex-failed', error: codexResult.error }`
    - Step 3: Both failed — behavior depends on `opts.taskCategory` (per D-17):
      - If `'review'` (fail-open): return `{ success: false, text: '', tokens: null, cost: 0, source: 'all-failed-review', error: 'Both Codex and MiniMax failed; review skipped (fail-open)', codexError: codexResult.error, minimaxError: minimaxResult.error }`
      - If `'execution'` (fail-closed): return `{ success: false, text: '', tokens: null, cost: 0, source: 'all-failed-execution', error: 'Both Codex and MiniMax failed; user intervention required (fail-closed)', codexError: codexResult.error, minimaxError: minimaxResult.error }`
