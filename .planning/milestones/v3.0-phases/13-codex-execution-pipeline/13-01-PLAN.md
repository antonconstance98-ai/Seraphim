<objective>
Transform gsd-executor from a code-writing Opus subagent into a thin orchestrator that generates natural language handoff specs and delegates code writing to Codex CLI, with MiniMax API as fallback when Codex is rate-limited, and user prompt as last resort (fail-closed).

Purpose: This is the biggest cost-saving change in v2.0 — moves all code generation off Opus tokens. Daily spend drops from ~$10-15 (Opus writing code) to ~$1-3 (Sonnet orchestrating + Codex executing for free via ChatGPT Plus subscription).

Output: codex-handoff.js helper module + modified gsd-executor.md agent definition
</objective>

    Create `~/.claude/hooks/codex-handoff.js` — a Node.js module that implements the three-tier execution fallback chain per D-08.

    **Single export: `executeHandoff(spec, opts)`**

    Parameters:
    - `spec` (string): Natural language handoff spec per D-01/D-02 format
    - `opts` (object):
      - `cwd` (string): Working directory for Codex CLI (required)
      - `targetFiles` (string[]): File paths the task creates/modifies (for MiniMax file-content injection per D-03/D-10)
      - `timeoutMs` (number, default 300000): Codex CLI timeout
      - `minimaxTimeoutMs` (number, default 90000): MiniMax API timeout

    Returns: `Promise<{ success: boolean, model: string, source: string, error: string|null, tokens: object|null, cost: number|null, minimaxText: string|null }>`
    - `model`: 'gpt-5.4' (Codex) or 'minimax-m2.7' (MiniMax) or null (both failed)
    - `source`: 'codex-cli' or 'api-fallback' or 'both-failed'
    - `minimaxText`: stripped file content from MiniMax (no think tags) — null unless MiniMax was used. The executor uses this to Write files to disk since MiniMax has no filesystem access.
    - `tokens`: token usage object from whichever model succeeded
    - `cost`: USD cost (null for Codex CLI which is free via subscription)

    **Implementation flow:**

    1. **Codex CLI attempt (primary):**
       - Call `runCodexExec(spec, { cwd: opts.cwd, timeoutMs: opts.timeoutMs })`
       - If `result.success === true`: return success with `model: 'gpt-5.4'`, `source: 'codex-cli'`, tokens from result
       - If `result.success === false`: check `isCodexRateLimited(result)`

    2. **MiniMax fallback (only on rate-limit per D-09, anti-pattern from research):**
       - If `isCodexRateLimited(result)` is FALSE: skip MiniMax, go directly to step 3 (user prompt). Non-rate-limit failures indicate config problems per Pitfall 4.
       - If TRUE: read each file in `opts.targetFiles` via `fs.readFileSync` (silently skip files that don't exist yet — they're being created). Augment spec with file content per D-03: append `\n\nCurrent file content for [path]:\n\`\`\`\n[content]\n\`\`\`` for each existing file.
       - Call `runMinimax(augmentedSpec, { maxTokens: 4000, timeoutMs: opts.minimaxTimeoutMs })` — use 4000 maxTokens since execution output is full file content, not a short review.
       - If `minimaxResult.success === true` AND `minimaxResult.text` is non-empty (Pitfall from Phase 10: empty text is feature-level failure):
         - Strip `<think>` block: find `</think>`, take content after it, `.trim()`. If no `</think>`, use full text.
         - Return success with `model: 'minimax-m2.7'`, `source: 'api-fallback'`, `minimaxText` = stripped content, tokens/cost from minimaxResult.
       - If failed: fall through to step 3.

    3. **User prompt (fail-closed per D-11):**
       - Return `{ success: false, model: null, source: 'both-failed', error: buildUserPromptMessage(codexResult, minimaxResult), minimaxText: null, tokens: null, cost: null }`
       - `buildUserPromptMessage`: format both error messages with the three options: (1) wait and retry Codex, (2) check MINIMAX_API_KEY, (3) skip this task. Never silently fall back to Opus.

    **After any successful execution, emit [CODEX_RESULT] marker to stdout per D-12:**
    ```
    console.log(`[CODEX_RESULT] ${JSON.stringify({ model, source, task_type: 'execution', tokens: normalizedTokens, rate_limit_pct: codexResult?.rateLimitPct || null })}`);
    ```
    This allows the existing codex-token-logger.js to capture execution events in token-log.jsonl.

    **Normalize token fields** before emitting the marker:
    - Codex tokens use: `input_tokens`, `cached_input_tokens`, `output_tokens`, `reasoning_output_tokens`
    - MiniMax tokens use: `input_tokens`, `cached_input_tokens`, `output_tokens` (no reasoning)
    - Marker format requires: `input_tokens`, `cached_input_tokens`, `output_tokens`, `reasoning_output_tokens` (set to 0 if absent)

    **Module header:** `codex-hook-version: 1.1.0`, document that this is a shared module (not a standalone hook), list Phase 13 as the consumer.

    **Lazy-require pattern** (consistent with Phase 11/12): require codex-exec, minimax-exec, and codex-pricing only inside the function body, not at module top level. This avoids loading the OpenAI SDK until actually needed.

    **Security per CLAUDE.md:** Never log API keys. The spec content may include file content but never credentials. Do not log the full spec to stdout (could contain sensitive code).
