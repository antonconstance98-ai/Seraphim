# Phase 09.1 Plan 03: Human/AI Task Views and /seraphim:tasks Command Summary

TaskList component with human/AI split views, amber badge on ProjectCard, and /seraphim:tasks terminal command backed by blueprint.md markers and forge-log.md status.

## What Was Built

### Task 1: TaskList component and project page update

Created `TaskList.tsx` — a reusable Server Component that renders either a human task list (amber-bordered cards with status badge) or an AI task table (phase, model, cost, outcome, latency columns). Outcome badges are color-coded: green for pass, amber for human_required, orange for loop_trigger, gray for others.

Updated `app/project/[name]/page.tsx` to:
- Import and use `TaskList` for both views
- Replace the old stub (which read `loop_trigger` outcome as human tasks) with correct filtering on `outcome === 'human_required'`
- Show AI tasks as the last 30 non-human-required decisions
- Human Tasks section uses amber heading with count badge when tasks exist

### Task 2: ProjectCard badge and /seraphim:tasks command

Updated `ProjectCard.tsx` to accept optional `humanTaskCount` prop (defaults to 0). When count > 0, renders an amber pill badge ("N human tasks") between the cost figure and the timestamp in the card footer.

Updated `app/page.tsx` to compute `humanTaskCount` per project by filtering `decisions` where `outcome === 'human_required'` — reuses the already-fetched decisions array, no additional query.

Created `commands/tasks.md` — the `/seraphim:tasks [phase-id]` command that:
1. Resolves project root via `.seraphim/config.json` walk
2. Reads `blueprint.md` and parses TASK markers, splitting by `assignee`
3. Reads `forge-log.md` (if present) for execution status per task
4. Prints Human Tasks and AI Tasks sections with status icons ([x], [!], [H], [-], [ ])
5. Prints a summary count and prompts for human action if tasks remain

## Deviations from Plan

None — plan executed exactly as written.
