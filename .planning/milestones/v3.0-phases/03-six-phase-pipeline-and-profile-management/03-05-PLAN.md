**Create commands/set-profile.md** — the `/seraphim:set-profile [name]` command (PROF-01, PROF-04, PROF-05, PROF-08).

Frontmatter:
```yaml
description: "Switch the active cost profile — controls which models run each pipeline phase"
argument-hint: "[profile-name]"
allowed-tools: ["Read", "Write", "Bash"]
```

Command body instructs Opus to:

1. **Resolve project root**: Find `.seraphim/config.json`. If not found, abort: "No Seraphim project found. Run /seraphim:new-project first."

2. **If no argument given** (per PROF-08): List all available profiles:
   - Read built-in profiles from `${CLAUDE_PLUGIN_ROOT}/config/profiles.json` — list all keys (performance, balanced, moderate, budget, frugal)
   - Scan `.seraphim/profiles/` directory for custom profiles (*.json files, strip extension for names)
   - If `.seraphim/` does not exist or has no profiles/ dir, show built-in only with note: "Custom profiles available after /seraphim:new-project"
   - Display the list with the current active profile marked, then prompt user to choose

3. **Validate profile name**: Check against built-in profile keys AND `.seraphim/profiles/` filenames. If not found, abort with: "Profile '{name}' not found. Available profiles: {list}". Per anti-pattern from research — do NOT silently accept invalid names.

4. **Check Qwen availability for Balanced/Budget** (per PROF-05): If the selected profile is `balanced` or `budget`, run `node -e "const q = require('${CLAUDE_PLUGIN_ROOT}/executors/qwen-exec'); q.available().then(a => console.log(a))"` via Bash. If result is `false`, print a clear warning: "Warning: Profile '{name}' uses Qwen 3.5-27B for {list_of_phases}. Qwen/ollama is currently unavailable. These phases will fail at runtime. Consider 'moderate' or 'performance' profile instead." Do NOT block the switch — the user may be planning to start ollama later. Just warn clearly.

5. **Update config**: Read current config, set `config.profile = name`, call `config.write()`.

6. **Record profile change event in state.json** (per Pitfall 5 from research): If a pipeline is in progress (any phase has state.json with at least one entry in profile_at_execution), append to the current phase's state.json: `{ profile_change_events: [{ from: "old", to: "new", changed_at: "ISO", effective_from_next_phase: true }] }` per D-04 (change takes effect on next phase).

7. **Print phase-to-model assignment table** (per PROF-01): Show all 10 phase slots with:
   - Phase name (human-friendly label)
   - Assigned model name
   - Whether the slot has an active override (mark with `*`)
   - If `opus_enabled: false`, show the fallback model instead of Opus for Opus-assigned slots (per PROF-04)
   - Estimated per-phase cost using models.json cost_per_mtok (assume ~2K tokens in + 2K tokens out per phase as rough estimate)

   Use the renderProfileTable pattern from the research code examples.

**Create commands/override.md** — the `/seraphim:override [phase] [model]` command (PROF-03).

Frontmatter:
```yaml
description: "Set a per-phase model override — changes one phase's model without switching the full profile"
argument-hint: "[phase-slot] [model-id]"
allowed-tools: ["Read", "Write", "Bash"]
```

Command body instructs Opus to:

1. **Resolve project root**, read config.

2. **Parse arguments**: Extract phase-slot and model-id. If missing or incomplete, show usage:
   ```
   Usage: /seraphim:override [phase-slot] [model-id]
   
   Phase slots:
     discover_external, discover_internal, envision, judge, architect,
     forge, forge_checkpoint_runtime, forge_checkpoint_static,
     crucible_verify, crucible_adversarial
   
   Model IDs:
     claude-opus-4-6, claude-sonnet-4-6, claude-haiku-4-5,
     codex-gpt-5.4, minimax-m2.7, gemini-3.1-pro, gemini-3-flash,
     qwen-3.5-27b, perplexity-sonar
   
   To clear an override: /seraphim:override [phase-slot] --clear
   ```

3. **Validate phase-slot**: Must be one of the 10 valid slot names. If invalid, show the list and abort.

4. **Validate model-id**: Must exist in models.json. If invalid, list available models and abort.

5. **Handle --clear**: If model argument is `--clear`, remove the override for that phase slot: delete `config.overrides[phase]` and write config.

6. **Set override**: `config.overrides[phase] = modelId`, then `config.write()`.

7. **Print confirmation**: Show what changed:
   ```
   Override set: {phase-slot} -> {model-name} ({model-id})
   Previous: {old-model-from-profile} (profile default)
   ```

8. **Print updated assignment table**: Same format as set-profile — show all 10 slots with the new override marked `*`.
