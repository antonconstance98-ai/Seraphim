**Create commands/run.md** — the `/seraphim:run [phase-id] [--from phase]` command (PIPE-08, PIPE-09).

Frontmatter:
```yaml
description: "Run the full six-phase Seraphim pipeline — Discover through Crucible"
argument-hint: "[phase-id] [--from discover|envision|judge|architect|forge|crucible]"
allowed-tools: ["Read", "Write", "Bash", "Edit", "Glob", "Grep", "WebFetch"]
```

Command body instructs Opus to:

1. **Resolve project root**: Find `.seraphim/config.json`. If not found, abort: "No Seraphim project found. Run /seraphim:new-project first."

2. **Parse arguments**: 
   - `phase-id` (required): The identifier for this pipeline run (e.g., "01-feature-name")
   - `--from [phase]` (optional): Resume from a specific phase. Valid values: discover, envision, judge, architect, forge, crucible.
   - If phase-id missing, abort with usage hint.

3. **Read config** to get max_loops and current profile.

4. **Define phase sequence as an ordered list** (per anti-pattern from research — NOT hardcoded if/else):
   ```
   PHASES = ["discover", "envision", "judge", "architect", "forge", "crucible"]
   ```

5. **Determine start point**:
   - If `--from` specified: Find the phase in the ordered list. Skip all phases before it. Validate that the `--from` phase is a valid phase name.
   - If no `--from`: Start from "discover".

6. **Print pipeline header banner**:
   ```
   ═══════════════════════════════════════════════════
    SERAPHIM  Full Pipeline Run
   ═══════════════════════════════════════════════════
    Phase ID:  {phase-id}
    Profile:   {profile-name}
    Starting:  {start-phase} ({--from or "beginning"})
    Phases:    {count} of 6
   ───────────────────────────────────────────────────
   ```

7. **Execute phases sequentially**: For each phase in the sequence (from start point):

   a. **Check loop state** (per Pitfall 4): Read state.json. Check loops.judge_envision and loops.crucible_forge against config.max_loops. If any loop counter is at or above the cap, halt: "Loop cap reached for {loop_type} ({count}/{max}). Human resolution required before continuing." Do NOT silently continue past the cap.

   b. **Check if phase output already exists** (for --from resume): If the output file for this phase exists AND the phase is before the --from target, skip it. This prevents re-running completed phases.

   c. **Invoke the phase command**: Instruct Opus to run the phase as if the user had typed `/seraphim:{phase} {phase-id}`. The run command does NOT re-implement each phase — it calls the existing phase commands. This means Opus should follow the instructions from that phase's command .md file.
   
   IMPORTANT: The run command orchestrates by invoking each phase command's logic in sequence. Since Claude Code commands are .md prompt files, Opus reads each command's instructions and executes them. The run.md must instruct Opus to: "For each phase, read the corresponding command file at `${CLAUDE_PLUGIN_ROOT}/commands/{phase}.md` and follow its instructions with the phase-id argument."

   d. **Check phase result**: After each phase completes, verify the output file was written:
      - discover: check discovery/external.md AND discovery/internal.md
      - envision: check vision.md
      - judge: check judgment.md
      - architect: check blueprint.md
      - forge: check forge-log.md
      - crucible: check crucible.md
   
   If the output file is missing, halt: "Phase {phase} failed to produce output. Check the error above and re-run with: /seraphim:run {phase-id} --from {phase}"

   e. **Auto-advance**: If phase completed successfully, proceed to next phase without user confirmation (this is the full-auto run mode).

8. **Print pipeline completion banner** after all phases finish:
   ```
   ═══════════════════════════════════════════════════
    SERAPHIM  Pipeline Complete
   ═══════════════════════════════════════════════════
    Phase ID:  {phase-id}
    Profile:   {profile-name}
    Phases:    6/6 complete
    Verdict:   {crucible verdict from crucible.md PHASE_COMPLETE marker}
    Total cost: ${sum}
   ───────────────────────────────────────────────────
   ```

9. **Mark pipeline complete** via `phase-state.js markComplete(projectRoot, phaseId)`.

**PIPE-11 Verification**: The `/seraphim:new-project` command already exists from Phase 1. Read it and verify it creates `.seraphim/` with config.json. If it needs updates to work with the new pipeline commands (e.g., creating the phases/ subdirectory structure), note the needed changes and make them. If it already handles this correctly, no changes needed — just confirm in the summary.
