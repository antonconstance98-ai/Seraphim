**Create commands/discover.md** — the `/seraphim:discover [phase-id]` command.

Frontmatter:
```yaml
description: "Run the Discover phase — gather external web research and internal codebase analysis"
argument-hint: "[phase-id]"
allowed-tools: ["Read", "Write", "Bash", "Glob", "Grep", "WebFetch"]
```

Command body instructs Opus to:

1. **Resolve project root**: Find `.seraphim/config.json` by checking cwd and parent dirs. If not found, abort: "No Seraphim project found. Run /seraphim:new-project first."

2. **Parse phase-id** from argument. If missing, abort with usage hint.

3. **Read config**: `node -e "const c = require('${CLAUDE_PLUGIN_ROOT}/lib/config'); console.log(JSON.stringify(c.read('${PROJECT_ROOT}')))"` via Bash.

4. **Record profile audit** (per D-05, Pitfall 3): Before any execution, write `profile_at_execution.discover_external` and `profile_at_execution.discover_internal` plus `model_at_execution` fields to state.json via a small Bash node script that calls phase-state.js writeState.

5. **Create output directory**: `mkdir -p .seraphim/phases/{phase-id}/discovery/`

6. **Run external track**: Resolve model for `discover_external` using `node -e "const d = require('${CLAUDE_PLUGIN_ROOT}/executors/dispatch'); const c = require('${CLAUDE_PLUGIN_ROOT}/lib/config').read('${PROJECT_ROOT}'); console.log(d.resolveExecutorId('discover_external', c))"`. 
   - If resolved model is `claude-opus-4-6`, Opus performs external research directly using WebFetch/Bash tools, then writes `external.md` with SERAPHIM:PHASE_START marker at top.
   - Otherwise, write a prompt file to `/tmp/seraphim-discover-ext-prompt.txt` containing: the user's phase description/goal, instructions to research external sources, and the SERAPHIM marker format. Then call `node ${CLAUDE_PLUGIN_ROOT}/executors/dispatch.js --phase discover_external --prompt-file /tmp/seraphim-discover-ext-prompt.txt --project-root ${PROJECT_ROOT} --output-file .seraphim/phases/{phase-id}/discovery/external.md`.
   - If dispatch fails, write a stub external.md with `<!-- SERAPHIM:TRACK_FAILED model="..." error="..." -->` (per Pitfall 6 from research).

7. **Run internal track**: Same pattern for `discover_internal`. The prompt instructs the model to analyze the project codebase (read key files, grep for patterns, understand architecture). Output to `internal.md` with markers.
   - If resolved model is `claude-opus-4-6`, Opus does the codebase analysis directly using Read/Grep/Glob tools.
   - Otherwise, dispatch via CLI. Note: external models have limited codebase access — the prompt should include key file contents extracted by Opus before dispatch.

8. **Print wing banner**: Use `node -e "const b = require('${CLAUDE_PLUGIN_ROOT}/lib/banner'); console.log(b.renderWingBanner('discover', {...}))"` with model, profile, status summary, cost.

9. **Mark phase progress**: Do NOT call markComplete (that's for the full pipeline). Just ensure state.json has the audit fields.

Research note: Per Open Question 1, run tracks sequentially (external first, then internal) in Phase 3. True parallelism is a future enhancement.

- Output format: write structured markdown with SERAPHIM markers to the discovery directory

**Create commands/envision.md** — the `/seraphim:envision [phase-id]` command.

Frontmatter:
```yaml
description: "Run the Envision phase — generate 3-5 divergent approaches from discovery findings"
argument-hint: "[phase-id]"
allowed-tools: ["Read", "Write", "Bash"]
```

Command body instructs Opus to:

1. **Resolve project root and phase-id** (same pattern as discover.md).

2. **Check prerequisite** (per Pattern 6 from research): Read `.seraphim/phases/{phase-id}/discovery/external.md` AND `internal.md`. Both must exist. If either is missing, abort: "Envision requires discovery output. Run /seraphim:discover {phase-id} first." If a file contains TRACK_FAILED marker, note it but proceed — partial discovery is acceptable.

3. **Read config and resolve model** for `envision` phase slot.

4. **Record profile audit**: Write `profile_at_execution.envision` and `model_at_execution.envision` to state.json BEFORE execution (per Pitfall 3).

5. **Conditional dispatch** (per Pitfall 2 from research — critical):
   - If resolved model is `claude-opus-4-6`: Opus generates the envision output DIRECTLY in the current session. Read both discovery files, then produce 3-5 distinct approaches with trade-offs. Write vision.md directly. Do NOT dispatch via CLI (avoids the Opus-calling-itself subagent problem).
   - If resolved model is anything else (e.g., `gemini-3.1-pro` in Moderate profile): Write a prompt file to `/tmp/seraphim-envision-prompt.txt` containing the full discovery content and instructions. Dispatch via `node ${CLAUDE_PLUGIN_ROOT}/executors/dispatch.js --phase envision --prompt-file ... --output-file .seraphim/phases/{phase-id}/vision.md`.

6. **Output format for vision.md**: Must include SERAPHIM markers:
   ```
   <!-- SERAPHIM:PHASE_START phase="envision" model="..." profile="..." timestamp="..." -->
   
   # Vision: {phase description}
   
   ## Approach 1: {name}
   <!-- SERAPHIM:APPROACH id="approach-1" -->
   [Description, trade-offs, risks, estimated effort]
   
   ## Approach 2: {name}
   <!-- SERAPHIM:APPROACH id="approach-2" -->
   ...
   
   (3-5 approaches total)
   
   <!-- SERAPHIM:PHASE_COMPLETE approach_count="N" -->
   ```

7. **Print Wing II banner** with model, profile, approach count, cost.

The envision prompt (whether inline or dispatched) must instruct the model to:
- Read and synthesize both discovery tracks
- Generate exactly 3-5 DISTINCT approaches (not variations of one idea)
- Each approach must have: name, description, trade-offs, risks, estimated complexity
- Include SERAPHIM:APPROACH markers with sequential ids
- End with SERAPHIM:PHASE_COMPLETE marker with approach_count
  </action>
