    Frontmatter:
    ```yaml
    ---
    description: "Add a new feature to a milestone's backlog"
    argument-hint: "[--name <name>] [--milestone <version>] [--slug <slug>] [--description <desc>] [--priority <N>]"
    allowed-tools: ["Read", "Bash"]
    ---
    ```

    **Step 1 — Resolve project root** (walk up from cwd looking for `.seraphim/config.json`).

    **Step 2 — Gather inputs interactively** (per D-04, same pattern as new-project.md):

    If flags are provided, use them. For any missing required field, prompt the user step-by-step:
    1. **name** (required): "What is the feature name?"
    2. **milestone** (required): Read roadmap, list available milestones with versions. If no milestones exist, prompt: "No milestones found. What milestone version should be created? (e.g., v3.1)". Also prompt for milestone name if creating new.
    3. **slug** (optional): "What slug for this feature? (leave blank to auto-generate from name)" — auto-generate by lowercasing name, replacing spaces with hyphens, removing non-alphanumeric chars.
    4. **description** (optional): "Brief description? (leave blank to skip)"
    5. **priority** (optional): Default to last position (append to end of features array). If provided, insert at that position.

    **Step 3 — Write feature to roadmap**

    Run a `node -e` script that:
    1. Requires roadmap.js
    2. Reads roadmap via `readRoadmap(projectRoot)`
    3. Finds or creates the target milestone (if milestone version doesn't exist, create `{ id: "ms-NNN", version: VERSION, name: NAME, status: "planned", features: [] }`)
    4. Generates feature ID via `nextFeatureId(roadmap)`
    5. Creates feature object per D-02 schema: `{ id, slug, name, description, status: "planned", depends_on: [], priority }`
    6. Inserts feature at correct priority position (or appends)
    7. Writes via `writeRoadmap(projectRoot, roadmap)`

    **Step 4 — Confirm**

    Print:
    ```
    Feature added to roadmap.
      ID:        feat-001
      Slug:      core-pm-primitives
      Milestone: v3.1 — Seraphim Project Management
      Status:    planned
      Priority:  1

    Start with: /seraphim:start feat-001
    ```

    Per ARCH-06/D-10: No sprint assignment, no story points, no time estimates in the command.

  <action>
    **Create `~/.claude/plugins/seraphim/commands/start.md`** that moves a feature to in-progress and launches the pipeline.

    Frontmatter:
    ```yaml
    ---
    description: "Start a feature — moves to in-progress, warns on WIP limit, launches pipeline"
    argument-hint: "<feature-id-or-slug>"
    allowed-tools: ["Read", "Bash"]
    ---
    ```

    **Step 1 — Parse arguments**: Extract the feature reference (first positional arg). Must accept both `feat-NNN` and slug format (per D-01). If missing, abort with usage message.

    **Step 2 — Resolve project root** (same walk-up pattern).

    **Step 3 — Check WIP limit and update status**

    Run a `node -e` script that:
    1. Requires roadmap.js and config.js
    2. Reads roadmap and config
    3. Finds feature via `findFeature(roadmap, ref)` — if not found, print error and exit
    4. If feature status is already `in-progress`, print "Feature is already in progress." and exit
    5. If feature status is `complete`, print "Feature is already complete." and exit
    6. Counts WIP via `countWip(roadmap)`
    7. Reads `config.max_wip` (default 2 from CONFIG_DEFAULTS)
    8. If `currentWip >= maxWip`, print WARNING (per D-06 — warn, not block):
       ```
       ⚠ WIP limit reached ({currentWip}/{maxWip} features in progress).
       Starting anyway. Adjust limit in .seraphim/config.json (max_wip field).
       ```
    9. Sets `feature.status = 'in-progress'`
    10. If milestone status is `planned`, sets it to `in-progress`
    11. Writes via `writeRoadmap(projectRoot, roadmap)`
    12. Prints the feature ID and slug for the pipeline delegation step

    **Step 4 — Launch pipeline**

    Instruct Claude to read `run.md` and follow its instructions, deriving the phase-id from the feature slug. Print:
    ```
    Feature started.
      ID:        {feature.id}
      Slug:      {feature.slug}
      Milestone: {milestone.version} — {milestone.name}
      WIP:       {newWipCount}/{maxWip}

    Launching pipeline via /seraphim:run...
    ```

    Then instruct: "Now read and execute `/seraphim:run {feature.slug}` to begin the six-phase pipeline for this feature."

    Per ARCH-01/D-08: If roadmap.json is missing, print "No roadmap found. Add features first with /seraphim:add-feature." — never error/crash.
  </action>
