Add a new exported function `readPmSummary(projectRoot)` to multi-project-scanner.js that returns:

```javascript
{
  projectName: string,       // path.basename(projectRoot)
  activeMilestone: {         // first milestone with status !== 'complete', or null
    version: string,
    name: string,
    percent: number          // from milestoneProgress()
  } | null,
  wip: number,               // from countWip()
  wipLimit: number,           // from config.js readConfig() wip_limit field, default 2
  pendingTasks: number,       // count of pending tasks from task-completions.jsonl + forge-log.md
  blockedFeatures: string[],  // feature IDs where depends_on has incomplete deps
  pendingGates: number        // count of human tasks with status 'pending'
}
```

Implementation details:
- Use `require('./roadmap')` for readRoadmap, countWip, milestoneProgress, findFeature
- Use `require('./config')` for readConfig (to get wip_limit)
- For pendingTasks: read `task-completions.jsonl` from `.seraphim/` to get completed task IDs, then scan forge-log.md files in `.seraphim/phases/*/forge-log.md` for `HUMAN_TASK:` markers not in completed set. This mirrors inbox.md's existing logic.
- For blockedFeatures: iterate all in-progress features, check each feature.depends_on array, filter to deps where findFeature returns null or status !== 'complete'
- Add readPmSummary to the module.exports object alongside existing exports

The command must:

1. Parse `$ARGUMENTS` for `--all` flag (default: active-only per D-01/OVER-03)

2. Run a node script that:
   - Calls `discoverSeraphimProjects([os.homedir() + '/projects', os.homedir() + '/agent'])`
   - For each project, calls `readPmSummary(project.root)`
   - Unless `--all`, filters out idle projects (wip===0 AND pendingTasks===0 AND pendingGates===0)
   - Builds attention signals array from all projects:
     * Blocked features: `[!] {projectName}  {featureId} ({featureName}) -- blocked (depends on {depId})`
     * WIP exceeded: `[!] {projectName}  WIP limit exceeded ({wip}/{wipLimit})`
     * Pending gates: `[!] {projectName}  {count} pending human gates`
   - Outputs structured text:
     * Header: `SERAPHIM  Overview`
     * If attention signals exist: `NEEDS ATTENTION` section with signals (per D-01)
     * Project table: `PROJECT  MILESTONE  WIP  TASKS` columns
     * Footer: `Idle projects hidden. Run /seraphim:overview --all to show all.` (only when not --all and idle projects were filtered)

3. Format the node output as the assistant's response using echo/console.log

Use the terminal output layout from the research doc (02-RESEARCH.md "Overview Terminal Output Design" section) as the template.
