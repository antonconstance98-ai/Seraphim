**4. Deduplication (PIPE-01):**

On startup, read existing `global.jsonl` (if it exists) line by line. Build a `Set` of dedup keys. The dedup key for each record is: `${record.session_id}|${record.timestamp}`. This handles null session_id because JavaScript's string interpolation produces `"null|2026-04-02T..."`, and the combination with millisecond-precise timestamp is unique across all observed records.

```javascript
function buildDedupKey(record) {
  return `${record.session_id}|${record.timestamp}`;
}
```

**5. Incremental reads (PIPE-03):**

Load `cache.json` (if exists) which stores per-file state:
```json
{
  "/home/alucard/projects/Claude_X_Codex/.planning/token-log.jsonl": {
    "mtime_ms": 1743548330644,
    "size": 4096,
    "byte_offset": 4096
  }
}
```

For each discovered file:
- `const stat = fs.statSync(filePath)` to get current `stat.mtimeMs` and `stat.size`.
- If `Math.floor(stat.mtimeMs)` equals cached `mtime_ms` AND `stat.size` equals cached `size`: skip entirely (file unchanged). This is the fast path that makes repeat runs complete in under 5 ms.
- If `stat.size` is greater than or equal to cached `byte_offset` and mtime changed: open a file descriptor with `fs.openSync(filePath, 'r')`, read from `byte_offset` to end using `fs.readSync` with `position: byte_offset`, parse only the new bytes as lines. Close the fd.
- If `stat.size` is less than cached `byte_offset` (file was truncated/rotated): re-read entire file from offset 0.
- If no cache entry: read entire file from offset 0 using `fs.readFileSync`.

For reading partial files, use synchronous I/O (not streams) to keep the logic simple and avoid async complexity in a hook context:
```javascript
function readFromOffset(filePath, offset) {
  const stat = fs.statSync(filePath);
  if (offset >= stat.size) return '';
  const buf = Buffer.alloc(stat.size - offset);
  const fd = fs.openSync(filePath, 'r');
  fs.readSync(fd, buf, 0, buf.length, offset);
  fs.closeSync(fd);
  return buf.toString('utf8');
}
```

**6. Record enrichment and appending:**

For each new line parsed from a source file:
- Parse as JSON. Skip malformed lines silently (try/catch around JSON.parse, continue on error).
- Compute dedup key via `buildDedupKey(rec)`.
- If key is in the seen `Set`: skip (already in global.jsonl).
- If new: enrich the record by adding three fields to a shallow copy:
  - `project_path`: absolute path to the project root (derived in step 3)
  - `project_name`: last segment of project_path (e.g., `"Claude_X_Codex"`)
  - `opus_baseline_usd`: call `computeOpusCost(rec.tokens)` from codex-pricing.js. The `rec.tokens` shape from token-log.jsonl is `{input, cached_input, output}` which matches `computeOpusCost`'s expected parameter shape. This always returns a number.
- Do NOT recompute `cost_usd` -- copy it as-is from the source record. It was already computed by codex-token-logger.js at logging time.
- Append the enriched record as a JSON line to `global.jsonl` using `fs.appendFileSync(globalPath, JSON.stringify(enriched) + '\n', 'utf8')`.
- Add the key to the seen `Set`.
- Increment the `recordsAdded` counter.

Records with `session_id: null` must NOT be dropped. The dedup key handles them via `"null|timestamp"`. When enriching, do NOT modify `session_id` -- leave it as `null` in global.jsonl. The dashboard generator (Phase 6) will handle grouping null-session records as "Unattributed".
