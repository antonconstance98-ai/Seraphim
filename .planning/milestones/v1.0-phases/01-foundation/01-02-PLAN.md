Create `/home/alucard/.claude/hooks/codex-exec.js` — a shared Node.js module (not a standalone hook) that other hooks `require()` to invoke Codex.

**This is NOT a hook script itself.** It exports functions. It does NOT read from stdin or write to stdout.

**Required exports:**

1. `runCodexExec(prompt, options)` — Spawns `codex exec --json --full-auto` as a child process.
   - Parameters:
     - `prompt` (string): The task prompt for Codex
     - `options` (object):
       - `cwd` (string): Working directory for Codex (default: process.cwd())
       - `timeoutMs` (number): Kill timeout in milliseconds (default: 300000 — 300s per FNDTN-02)
       - `model` (string): Model to use (default: 'gpt-5.4')
   - Spawns: `codex exec --json --full-auto --model {model} {prompt}` via `child_process.spawn`
   - Timeout: `setTimeout` kills process with SIGTERM at `timeoutMs`. If SIGTERM is ignored, SIGKILL after 5s grace period.
   - Collects all stdout into a buffer (JSONL lines)
   - Returns a Promise that resolves to:
     ```javascript
     {
       success: true/false,
       exitCode: number,
       output: string,        // raw stdout (all JSONL lines)
       tokens: { ... },       // parsed from last token_count event (or null)
       rateLimitPct: number,  // from rate_limits.primary.used_percent (or null)
       error: string|null     // error message if failed/timed out
     }
     ```
   - On timeout, resolves (does NOT reject) with `{ success: false, error: 'codex exec timed out after 300s', ... }`
   - On spawn error (codex not found, permission denied), resolves with `{ success: false, error: err.message, ... }`

2. `parseCodexTokens(jsonlOutput)` — Parses JSONL output from `codex exec --json` and extracts cumulative token usage.
   - Parameter: `jsonlOutput` (string): Raw JSONL output (multiple lines)
   - Splits by newline, JSON.parse each line
   - Finds ALL lines where `type === 'event_msg'` and `payload.type === 'token_count'` and `payload.info !== null`
   - Takes the LAST such line (cumulative totals, not first which has null info — Pitfall 3)
   - Returns:
     ```javascript
     {
       input_tokens: number,
       cached_input_tokens: number,
       output_tokens: number,
       reasoning_output_tokens: number,
       total_tokens: number,
       rate_limit_pct: number|null  // from rate_limits.primary.used_percent
     }
     ```
   - Returns `null` if no valid token_count event found

3. `computeCost(tokens, model)` — Computes USD cost from token counts.
   - Parameter: `tokens` (object from parseCodexTokens), `model` (string)
   - Pricing constants (verified 2026-04-02, hardcoded with date comment):
     ```javascript
     // Pricing as of 2026-04-02 — update if stale
     const PRICING = {
       'gpt-5.4':      { input: 2.50, cached_input: 1.25, output: 10.00 },  // per 1M tokens
       'gpt-5.4-mini': { input: 0.40, cached_input: 0.20, output: 1.60 },
     };
     ```
   - Formula: `(tokens.input_tokens * price.input + tokens.cached_input_tokens * price.cached_input + tokens.output_tokens * price.output) / 1_000_000`
   - Returns: number (USD, 6 decimal places)

**Implementation rules:**
- Use `require('child_process').spawn` — NOT `exec` (exec buffers entire output; spawn streams)
- Use `require('path')` and `require('fs')` — no external dependencies
- The codex binary path: just `'codex'` (it's in PATH at `~/.npm-global/bin/codex`)
- Do NOT log or echo `process.env.OPENAI_API_KEY` anywhere (security rule)
- Pass `env: process.env` to spawn so Codex inherits the API key from environment
- Add `module.exports = { runCodexExec, parseCodexTokens, computeCost };` at the end
- Add a header comment: `// codex-exec.js — Shared Codex execution wrapper for Claude Code hooks`
- Add `// codex-hook-version: 1.0.0` after the shebang

Create `/home/alucard/.claude/hooks/codex-token-logger.js` — a PostToolUse hook that logs token usage after Codex calls.

**This IS a standalone hook script.** It reads JSON from stdin, processes it, outputs JSON to stdout. Follows the established pattern from gsd-context-monitor.js.

**How it works:**
This hook fires after tool use. It checks if the tool result indicates a Codex call was made (by looking for a marker in the tool_result). If so, it extracts token data and appends a record to `.planning/token-log.jsonl`.

**Implementation — exact structure:**

```javascript
#!/usr/bin/env node
// codex-hook-version: 1.0.0
// Token Logger — PostToolUse hook
// Appends a JSONL record to .planning/token-log.jsonl after every Codex call.
// Covers both CLI calls (from codex exec --json) and API calls (from openai SDK).
// Required by: TRCK-01 (every call logged), TRCK-02 (both providers covered)

const fs = require('fs');
const path = require('path');
```

1. **Stdin timeout guard** — 10s timeout, same as gsd-context-monitor.js
2. **Read stdin JSON** — parse `data` object with `session_id`, `cwd`, `tool_name`, `tool_result`
3. **Check for Codex marker** — look for `[CODEX_RESULT]` prefix in `tool_result` string. If not present, `process.exit(0)` (not a Codex call, nothing to log).
4. **Parse Codex result** — the marker format is:
   ```
   [CODEX_RESULT] {"model":"gpt-5.4","source":"cli","task_type":"implementation","tokens":{...},"rate_limit_pct":3.0}
   ```
   Extract JSON after the `[CODEX_RESULT] ` prefix.
5. **Build log record** — TRCK-01 requires: model, task_type, tokens_in, tokens_out, cost, timestamp
   ```javascript
   const { computeCost } = require('./codex-exec');
   const record = {
     timestamp: new Date().toISOString(),
     session_id: data.session_id,
     model: codexResult.model,           // 'gpt-5.4' or 'gpt-5.4-mini'
     source: codexResult.source,          // 'cli' or 'api'
     task_type: codexResult.task_type,    // 'implementation'|'test-gen'|'review'|'bulk-ops'
     tokens: {
       input: codexResult.tokens.input_tokens || 0,
       cached_input: codexResult.tokens.cached_input_tokens || 0,
       output: codexResult.tokens.output_tokens || 0,
       reasoning_output: codexResult.tokens.reasoning_output_tokens || 0
     },
     cost_usd: computeCost(codexResult.tokens, codexResult.model),
     rate_limit_pct: codexResult.rate_limit_pct || null
   };
   ```
6. **Append to token log** — use `fs.appendFileSync`:
   ```javascript
   const logPath = path.join(data.cwd, '.planning', 'token-log.jsonl');
   // Create .planning dir if it doesn't exist
   const planningDir = path.join(data.cwd, '.planning');
   if (!fs.existsSync(planningDir)) {
     fs.mkdirSync(planningDir, { recursive: true });
   }
   fs.appendFileSync(logPath, JSON.stringify(record) + '\n', 'utf8');
   ```
7. **Output advisory context** — let Claude know a token record was logged:
   ```javascript
   const output = {
     hookSpecificOutput: {
       hookEventName: 'PostToolUse',
       additionalContext: `[Codex Token Log] ${codexResult.model} ${codexResult.task_type}: ${record.tokens.input + record.tokens.output} tokens, $${record.cost_usd.toFixed(4)}`
     }
   };
   process.stdout.write(JSON.stringify(output));
   ```
8. **Error handling** — wrap everything in try/catch, `process.exit(0)` on any error (never block tool execution)
