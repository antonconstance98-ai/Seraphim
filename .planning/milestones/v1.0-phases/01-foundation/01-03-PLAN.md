Create `/home/alucard/.claude/hooks/codex-router.js` — a PreToolUse hook that intercepts Write/Edit tool calls and injects a Codex routing advisory when conditions are met.

**This IS a standalone hook script.** It reads JSON from stdin, checks routing conditions, and outputs advisory JSON to stdout. It follows the exact pattern from claude-settings-guard.js and gsd-context-monitor.js.

**Behavior (step by step):**

1. **Shebang and header:**
   ```javascript
   #!/usr/bin/env node
   // codex-hook-version: 1.0.0
   // Codex Router — PreToolUse hook
   // Intercepts Write/Edit tool calls and advises Claude to delegate implementation
   // tasks to Codex when routing is enabled in the project config.
   // Required by: FNDTN-03, ROUT-03, ROUT-04
   // Gap closure: Phase 1 verification found this hook missing
   ```

2. **Stdin timeout guard** — 5s timeout (same as claude-settings-guard.js, PreToolUse hooks use 5s not 10s):
   ```javascript
   const stdinTimeout = setTimeout(() => process.exit(0), 5000);
   ```

3. **Read and parse stdin JSON** — collect chunks, JSON.parse on end event. On parse error, `process.exit(0)` (silent fail).

4. **Check tool_name** — only process `Write` or `Edit` tool calls. If tool_name is anything else, `process.exit(0)`.

5. **Read project-scope config** — read `{data.cwd}/.claude/settings.json`:
   ```javascript
   const cwd = data.cwd || process.cwd();
   const configPath = path.join(cwd, '.claude', 'settings.json');
   ```
   If the file does not exist, `process.exit(0)` (no config = no routing).
   Parse JSON. If `config.codex?.routing_enabled !== true`, `process.exit(0)` (D-07: opt-in OFF by default).

6. **Extract config values** for ROUT-03 and ROUT-04:
   ```javascript
   const preferredModel = config.codex?.preferred_model || 'gpt-5.4';     // ROUT-04
   const apiModel = config.codex?.api_model || 'gpt-5.4-mini';            // ROUT-04
   const fallbackBehavior = config.codex?.fallback_on_error || 'prompt_user'; // ROUT-03
   const attribution = config.codex?.attribution_enabled !== false;         // D-08
   const timeoutSeconds = config.codex?.timeout_seconds || 300;            // FNDTN-02
   ```

7. **Detect if this is a Codex-appropriate task** (D-05, D-06). Check `data.tool_input`:
   - Get `file_path` from `data.tool_input.file_path || ''`
   - Get `content` from `data.tool_input.content || data.tool_input.new_string || ''`
   - The hook should inject advisory context for ALL Write/Edit calls when routing is enabled. The advisory tells Claude to consider delegating to Codex. Claude (Opus) decides whether to actually delegate based on the task context. This is Phase 1 — advisory only, not blocking.
   - Do NOT attempt to classify task types via content heuristics in Phase 1. The research notes that "Universal auto-routing via prompt analysis" is out of scope (keyword classification is fragile). The routing hook advises; Opus decides.

8. **Build advisory context message** — inject `additionalContext` telling Claude that Codex routing is active:
   ```javascript
   const advisoryParts = [
     '[Codex Router] Routing is ENABLED for this project.',
     `Preferred CLI model: ${preferredModel} (subscription). API model: ${apiModel}.`,
     'Consider delegating this Write/Edit operation to Codex if it is:',
     '  - A clearly-defined implementation task with a spec',
     '  - Test generation (unit/integration tests)',
     '  - Bulk file operations (rename, reformat, migrate)',
     '  - Code review or diff analysis',
     'Do NOT delegate: architecture decisions, debugging, exploratory analysis, security-sensitive operations.',
   ];

   if (fallbackBehavior === 'prompt_user') {
     advisoryParts.push('On Codex failure: prompt the user (fail-closed, per ROUT-03). Do NOT silently fall back to Opus.');
   }

   if (attribution) {
     advisoryParts.push('Attribution: note which model handled the work in your response (per D-08).');
   }

   advisoryParts.push(`Codex timeout: ${timeoutSeconds}s. Use require("./codex-exec").runCodexExec() to invoke.`);
   ```

9. **Output advisory JSON** — use the `additionalContext` pattern (NOT `permissionDecision: 'deny'`). This is advisory, not blocking:
   ```javascript
   const output = {
     hookSpecificOutput: {
       hookEventName: 'PreToolUse',
       additionalContext: advisoryParts.join('\n')
     }
   };
   process.stdout.write(JSON.stringify(output));
   process.exit(0);
   ```

10. **Error handling** — wrap everything in try/catch. On any error, `process.exit(0)` (silent fail, never block tool execution).

**Implementation rules:**
- Use `require('fs')` and `require('path')` only — no external dependencies
- Do NOT `require('./codex-exec')` in this hook — the router only advises, it does not invoke Codex directly. Opus invokes Codex using codex-exec.js when it decides to delegate.
- Do NOT block (deny) tool calls — this is advisory only in Phase 1
- Do NOT log or reference `process.env.OPENAI_API_KEY` anywhere
- Exit code 0 always (advisory hook, never blocks)
- The hook must complete in under 5 seconds (timeout in settings.json registration)
