   - Before emitting the HUMAN_TASKS marker, add instructions for Claude to analyze the task context and populate enrichment fields:
     - `skills_to_learn`: comma-separated list of skills the human should learn to handle this task type independently (e.g., "TypeScript,SQL,Docker"). Only populate when the task involves learnable skills.
     - `thought_prompt`: a single question that prompts the human to think deeply about the task's broader implications (e.g., "How does this authentication change affect your security model?"). Only populate for tasks with strategic implications.
     - `research_task`: a specific research action the human should take (e.g., "Read the Stripe webhook documentation section on idempotency"). Only populate when external research would help.

   - After a task fails, before surfacing to human:
     - Read `.planning/debug/repair-history.jsonl` if it exists (append-only log of repair attempts)
     - Call `selectStrategy(failedTask, repairHistory)` from lib/repair.js
     - If strategy is RETRY: re-run the failed task (up to 2 times)
     - If strategy is DECOMPOSE: instruct Claude to split the task into 2-3 subtasks and attempt each
     - If strategy is ESCALATE: surface to human with full context (what was tried, why it failed)
     - Append each repair attempt to `.planning/debug/repair-history.jsonl` with: `{task_id, strategy, timestamp, success}`
   - Per DBG-02: If failure comes from a verification/UAT context, spawn a debug session with `--from-uat` flag linking to the gap

3. Keep PRUNE as a documented option but do not auto-select it — it requires human judgment about which dependency to remove.
