**Library mode (exported function):**

`async function compress(text, opts)` per D-02:
- `opts.maxOutputTokens` — default 1500
- `opts.purpose` — string guiding compression behavior (per D-07). Supported purposes and their preservation rules:
  - `'summarize code diff'`: file names/paths, function/method signatures added/removed, nature of each change (bug fix, feature, refactor), error handling additions/removals
  - `'condense tool output'`: error messages and stack traces (verbatim), key data values and counts, actionable warnings or failures, success/failure status
  - `'compress conversation'`: decisions made and rationale, blockers and open questions, action items and next steps, file paths and function names mentioned
  - `'condense file content'`: function and class signatures, public API surface, important constants and configuration, critical logic flows
  - **Generic fallback** (for any unknown purpose string): 'All actionable and technical information, error messages, file paths, function names, data values, and status indicators'
- Estimate input tokens: `Math.round(text.length / 4)` (4 chars per token heuristic — established pattern, +-15% accurate, sufficient for threshold comparison)
- Lazy-require `runMinimax` from `/home/alucard/.claude/hooks/minimax-exec` (same lazy pattern as Phase 11 — only pay SDK load cost when compression actually fires)
- Build purpose-aware compression prompt via `buildCompressionPrompt(text, purpose)`:
  - Prompt template: `Summarize the following content as concisely as possible while preserving:\n${ruleList}\n\nDo not add commentary. Output only the compressed summary.\n\n---\n${text}`
  - System prompt: `'You are a technical summarizer. Preserve all actionable information.'`
- Call `runMinimax(prompt, { maxTokens, timeoutMs: 60000, systemPrompt })` — 60s timeout accounts for MiniMax pre-answer latency (documented up to 55s on first call)
- On failure (`result.success === false`): return `{ success: false, text: '', error: result.error }`
- On success: strip think tags via `result.text.replace(/<think>[\s\S]*?<\/think>\s*/g, '').trim()` (identical regex from Phases 10-11), prepend header `[Compressed from ~{N}K tokens]\n` per D-08 where N = `Math.round(approxInputTokens / 1000)`
- Truncate final output to 9500 chars max via `.slice(0, 9500)` (leave 500-char buffer under 10K additionalContext ceiling)
- Return: `{ success: true, text: headerPlusCompressed, tokens: result.tokens, cost: result.cost, originalChars: text.length, compressedChars: output.length }`

**Hook mode (PostToolUse):**

Guarded by `if (require.main === module) { runAsHook(); }`. Inside `async function runAsHook()`:
- Read stdin with 10s timeout guard: `const stdinTimeout = setTimeout(() => process.exit(0), 10000);` (same as minimax-post-scan.js and gsd-context-monitor.js)
- Parse JSON from stdin, extract `data.tool_result`, `data.session_id`, `data.cwd`
- **tool_result coercion** (addresses review concern about non-string results): `const toolResult = typeof data.tool_result === 'string' ? data.tool_result : (data.tool_result != null ? JSON.stringify(data.tool_result) : '');` — this handles objects, arrays, null, and undefined safely
- **Double-compression guard** (addresses review concern about robustness): `if (toolResult.includes('[Compressed from ~'))` instead of `.startsWith()` — catches the header even if preceded by whitespace or other text. Exit(0) silently if detected.
- Read project settings from `path.join(cwd, '.claude', 'settings.json')` to get minimax config block. If file missing or parse error, use defaults.
- If `minimaxConfig && minimaxConfig.enabled === false`, exit(0)
- Compute threshold in chars: `const thresholdChars = ((minimaxConfig && minimaxConfig.compress_tool_output_tokens) || 10000) * 4;` — converts D-03 token threshold to chars using the 4-char heuristic
- If `toolResult.length <= thresholdChars`, exit(0) silently (most common path — fast exit for short outputs)
- Call `compress(toolResult, { purpose: 'condense tool output', maxOutputTokens: 1500 })`
- If compression succeeds (`result.success === true`):
  - Write stdout: `JSON.stringify({ hookSpecificOutput: { hookEventName: 'PostToolUse', additionalContext: result.text } })`
  - Token logging (only on success with tokens present): lazy-require `computeCodexCostStrict`, write record to `.planning/token-log.jsonl` using the exact schema from the interfaces section above. Guard the entire logging block in try/catch (logging errors are non-fatal).
- If compression fails: exit(0) silently (advisory, never blocks)
- Outer try/catch around entire runAsHook: exit(0) on any unexpected error

**Module exports:** `module.exports = { compress };`

Important implementation notes:
- Do NOT use `execSync` or `execFileSync` — compression is pure API call, no subprocess needed
- Only export `compress`. Keep `buildCompressionPrompt` and `runAsHook` private (not exported)
- File header comment should include `codex-hook-version: 1.0.0` and list the decisions implemented (D-02, D-03, D-04, D-07, D-08)
