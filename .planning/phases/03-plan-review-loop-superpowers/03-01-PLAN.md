Create `~/.claude/hooks/codex-multi-round-reviewer.js` as a Node.js module that implements the 5-step multi-round review loop per D-01.

**Module signature:**
```javascript
async function runMultiRoundReview(cwd, phase, planContent, options)
// options: { maxRounds: 3, taskType: 'phase-plan'|'task-plan'|'superpowers-plan', sessionId: string|null }
// Returns: { rounds: Array, handoffSpec: string, hasBlockingIssues: boolean, reviewsPath: string, verdict: string, earlyExit: boolean }
```

**Implementation details:**

1. **State management functions** — `loadOrInitState(stateFile, opts)` and `advanceRound(stateFile, state, roundNum)` and `recordRoundResult(stateFile, state, roundNum, result)`:
   - State file path: `path.join(cwd, '.planning', 'review-state.json')`
   - Schema: `{ schema_version: 1, phase, max_rounds, current_round, started_at, rounds: [], status: 'in_progress' }`
   - On load: if file exists AND `status === 'in_progress'` AND `phase` matches, resume from `current_round`. Otherwise reinitialize.
   - Write state file BEFORE every Codex call (Pitfall 1 mitigation — prevents restart on crash)
   - On completion: set `status: 'complete'`

2. **Two distinct prompts** (per D-01, Pitfall 5):
   - `CONSTRUCTIVE_PROMPT`: "You are a constructive reviewer. For each plan, identify: 1. Missing or vague task actions (would an executor need clarification?) 2. Missing verification commands 3. Dependency issues (references a file from a later wave) 4. File conflicts (same file modified by parallel plans) 5. Requirements coverage gaps. For each issue: [PLAN {id}] [SEVERITY: HIGH|MEDIUM|LOW] {description}. If no issues: output exactly 'PLANS APPROVED — no issues found'"
   - `ADVERSARIAL_PROMPT`: "You are a skeptical adversarial reviewer. Challenge every assumption. Do NOT be constructive. Your job is to find what can go wrong: 1. What edge cases are not handled? 2. What assumptions does the plan rely on that could be false? 3. What is the simplest way this plan could fail in production? 4. What did the author over-simplify or get wrong? 5. What requirements are technically satisfied but practically broken? For each concern: [CONCERN] [SEVERITY: HIGH|MEDIUM|LOW] {description}. If the plan is genuinely robust: output 'ADVERSARIAL REVIEW PASSED — no vulnerabilities found'"

3. **Loop flow** (per D-01, D-02):
   - Round 1 (always runs): Call `runCodexExec` with constructive prompt + plan content. timeoutMs: 180000. model: 'gpt-5.4'. Extract text via `extractCodexText` (copy from codex-plan-reviewer.js). Parse issue count by counting lines matching `[SEVERITY:`.
   - Early exit check (D-02): If round 1 output contains "PLANS APPROVED" or has zero `[SEVERITY:` matches, set `earlyExit: true`, skip round 2, write handoff spec with verdict "APPROVED".
   - Round 2 (only if round 1 found issues): Call `runCodexExec` with adversarial prompt + plan content. timeoutMs: 180000. model: 'gpt-5.4'. Extract text. Check for HIGH severity via `/\[SEVERITY:\s*HIGH\]/i`.

4. **Milestone updates to stderr** (per D-06): Write progress to stderr (not stdout — stdout is reserved for hook JSON response):
   - Before round 1: `process.stderr.write('codex-multi-round: Round 1 — Codex constructive review starting...\n')`
   - After round 1: `process.stderr.write('codex-multi-round: Round 1 complete — {N} issues found.\n')` or `'...0 issues, early exit.\n'`
   - Before round 2: `process.stderr.write('codex-multi-round: Round 2 — Codex adversarial review starting...\n')`
   - After round 2: `process.stderr.write('codex-multi-round: Round 2 complete — {N} concerns raised.\n')`

5. **Handoff spec writer** — `writeHandoffSpec(phaseDir, paddedPhase, results, state)`:
   - File path: `path.join(phaseDir, paddedPhase + '-HANDOFF.md')`
   - Content (markdown):
     ```
     # Phase {paddedPhase} — Review Handoff Spec

     **Reviewed:** {ISO timestamp}
     **Rounds completed:** {1 or 2}
     **Early exit:** {yes/no}
     **Model authority:** Opus 4.6 (final authority per D-03)

     ## Plan Changes from Review

     {Round 1 constructive findings — full text from Codex}

     ## Adversarial Review

     {Round 2 adversarial findings — full text, or "Skipped (early exit — no issues in round 1)"}

     ## Decisions Not Taken

     | Issue | Raised by | Round | Reason Not Implemented |
     |-------|-----------|-------|------------------------|
     {Extract HIGH/MEDIUM severity items from round 2 that Opus did not address — these are populated by the caller after Opus makes its final revision. Initially left as: "To be populated after Opus final revision"}

     ## Review Verdict

     {APPROVED | APPROVED_WITH_CHANGES | BLOCKED_HIGH_SEVERITY}
     ```
   - Return the file path

6. **Token logging**: After each Codex round, append a record to `.planning/token-log.jsonl` with `task_type: 'multi-round-plan-review'`, `round: N`, `review_type: 'constructive'|'adversarial'`. Use the same record format as codex-plan-reviewer.js (timestamp, session_id, model, source, task_type, tokens, cost_usd, rate_limit_pct).

7. **Error handling**: If any Codex call fails, log to stderr and return `{ success: false, error: ... }`. The caller (codex-plan-reviewer.js) handles fail-open behavior.

8. **Module export**: `module.exports = { runMultiRoundReview };`
