Create `~/.claude/commands/gsd/dismiss-last.md` as a GSD slash command.

**Frontmatter:**
```yaml
---
name: gsd:dismiss-last
description: Dismiss the most recent false-positive review BLOCK, creating a negative training signal.
allowed-tools:
  - Read
  - Write
  - Bash
  - Grep
---
```

**Objective section:**
Dismiss the most recent BLOCK event in decision-log.jsonl for this project. This creates an explicit negative training signal that Phase 16's noise profile system will use to suppress frequently-dismissed review rules.

**Process (inline workflow — no separate workflow file needed):**

The command instructs Claude to perform these steps:

1. **Find the log file**: Read `.planning/decision-log.jsonl` in the current project directory. If the file doesn't exist or is empty, report "No decision log found for this project" and stop.

2. **Scan backward for last BLOCK**: Read the file, parse each line as JSON, find the LAST record where `review_verdict === "BLOCK"` AND `outcome === null` (not already dismissed). Per D-04: target BLOCK events only, never scans. Use `event_type === "Stop"` as additional guard per Pitfall 3.

3. **If no undismissed BLOCK found**: Report "No undismissed BLOCK events found in this project's decision log" and stop.

4. **Count prior dismissals for this category**: Count records in the last 30 days where `review_block_category` matches the found BLOCK's category AND `outcome === "dismissed"`. This gives the dismiss count for the feedback message.

5. **Append dismiss record**: Append a NEW JSONL line (never modify existing records — JSONL is append-only) with these fields:
   ```json
   {
     "schema_version": 1,
     "timestamp": "<current ISO timestamp>",
     "session_id": "<from original BLOCK record>",
     "ref_timestamp": "<timestamp of the original BLOCK record>",
     "event_type": "dismiss",
     "review_block_category": "<from original BLOCK>",
     "outcome": "dismissed",
     "dismissed_at": "<current ISO timestamp>",
     "project": "<from original BLOCK>",
     "cwd": "<current working directory>"
   }
   ```

6. **Show feedback** (per D-05): Display a message like:
   > Dismissed. This is dismissal **2 of 3** for rule "correctness" in the last 30 days. One more and it will be auto-suppressed.
   
   Or if this is the first dismissal:
   > Dismissed. This is the **first** dismissal for rule "correctness". After 3 dismissals in 30 days, this rule will be auto-suppressed.
   
   Or if this is the 3rd:
   > Dismissed. Rule "correctness" has been dismissed **3 times** in 30 days and is now eligible for auto-suppression by the noise profile system.

The command runs inline (no Task, no Agent). It uses Read to load the JSONL, Bash to append the dismiss record (via a `node -e` one-liner using fs.appendFileSync), and prints the feedback message directly.

**freeze.md** — Create `~/.claude/commands/gsd/freeze.md`:

**Frontmatter:**
```yaml
---
name: gsd:freeze
description: Freeze adaptive behavior — revert to static v2.0 rules instantly.
allowed-tools:
  - Read
  - Write
  - Bash
---
```

**Process (inline):**

1. Read the project's `.claude/settings.json` (at `{cwd}/.claude/settings.json`, per Pitfall 4 — NEVER write to `~/.claude/settings.json` which is user-scope and would freeze ALL projects).
2. If file doesn't exist, create it with `{ "adaptive": false }`.
3. If file exists, parse JSON, set `adaptive` key to `false` at the root level (sibling of `codex` and `minimax`, not nested inside them).
4. Write back using atomic write-then-rename pattern: write to `.claude/settings.json.tmp`, then rename to `.claude/settings.json`.
5. Confirm: "Adaptive behavior frozen. System will use static v2.0 rules. Run `/gsd:unfreeze` to re-enable."

Per D-07: `adaptive: false` disables everything adaptive — auto-tuning, noise profiles, routing weight adjustments. Future adaptive hooks (Phases 16-17) check this flag at the start of their logic and exit silently if false.

**unfreeze.md** — Create `~/.claude/commands/gsd/unfreeze.md`:

**Frontmatter:**
```yaml
---
name: gsd:unfreeze
description: Re-enable adaptive behavior after a freeze.
allowed-tools:
  - Read
  - Write
  - Bash
---
```

**Process (inline):**

1. Read the project's `.claude/settings.json` (at `{cwd}/.claude/settings.json`).
2. If file doesn't exist, create it with `{ "adaptive": true }`.
3. If file exists, parse JSON, set `adaptive` key to `true` at root level.
4. Write back atomically (same write-then-rename pattern).
5. Confirm: "Adaptive behavior re-enabled. System will resume learning from decisions."

Both commands are simple inline workflows — no separate workflow files, no Task/Agent tools.
