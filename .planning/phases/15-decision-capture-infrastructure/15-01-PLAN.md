**hook-signal.js** — Shared state module (per D-02: shared state over advisory text parsing).

Create `~/.claude/hooks/hook-signal.js` exporting four functions.

**CRITICAL DESIGN — Append-only state (addresses R2 locking concern):**
`writeHookSignal` does NOT read-merge-write. Instead, it appends a JSON line to the state file. Each call appends one line: `JSON.stringify({[key]: value}) + '\n'`. The `readHookState` function reads ALL lines and merges them (last value for each key wins). This eliminates the read-merge-write race entirely — `fs.appendFileSync` is atomic for small writes under PIPE_BUF on POSIX.

**Event ID — deterministic from stdin payload (addresses R1+R2 keying concerns):**
The event_id is computed from fields present in every hook's stdin:
- PostToolUse: `crypto.createHash('sha256').update(session_id + '\0' + tool_name + '\0' + JSON.stringify(tool_input || {})).digest('hex').slice(0, 16)`
- Stop: `crypto.createHash('sha256').update(session_id + '\0stop\0' + (content || '').slice(0, 200)).digest('hex').slice(0, 16)`

Uses SHA-256 (NOT MD5 — addresses R2 integrity concern) truncated to 16 hex chars (64 bits, not 32 bits — addresses R2 collision concern). The NUL byte separator prevents field-boundary ambiguity.

**State file location:** `{cwd}/.planning/.hook-state/{eventId}.jsonl` (NOT /tmp).

1. `buildEventId(data)` — Takes the full hook stdin `data` object. Returns a 16-char hex string.
   - If `data.tool_name` is defined (PostToolUse): hash `data.session_id + '\0' + data.tool_name + '\0' + JSON.stringify(data.tool_input || {})`
   - If `data.tool_name` is undefined (Stop): hash `data.session_id + '\0stop\0' + (data.content || '').slice(0, 200)`
   - If `data.session_id` is falsy: return `'no-session-' + Date.now()` (fallback — will still correlate within the same millisecond, and stderr warns)

2. `writeHookSignal(cwd, eventId, key, value)` — Path: `{cwd}/.planning/.hook-state/{eventId}.jsonl`. Creates `.hook-state/` dir if missing (`fs.mkdirSync({recursive:true})`). Appends one line: `fs.appendFileSync(path, JSON.stringify({[key]: value}) + '\n', 'utf8')`. On error: `process.stderr.write('[hook-signal] write error: ' + err.message + '\n')`. Does NOT throw.

3. `readHookState(cwd, eventId)` — Reads the `.jsonl` state file, splits by `\n`, parses each line, merges all objects into one (later lines override earlier for same key). Returns merged object. On error (file missing, parse error): `process.stderr.write('[hook-signal] read warning: ' + err.message + '\n')` and returns `{}`.

4. `cleanupHookState(cwd, eventId)` — Deletes the state file via `fs.unlinkSync`. On error: log to stderr (ENOENT = fine, other = warn). Then runs stale sweep: `fs.readdirSync` the `.hook-state/` dir, delete any `.jsonl` file with mtime older than 1 hour. Stale sweep errors are logged but never throw.

All four functions are synchronous. Module exports: `{ buildEventId, writeHookSignal, readHookState, cleanupHookState }`.
