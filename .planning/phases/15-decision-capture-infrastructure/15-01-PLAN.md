**hook-signal.js** — Shared state module (per D-02: shared state over advisory text parsing).

Create `~/.claude/hooks/hook-signal.js` exporting four functions:

**CRITICAL DESIGN (addresses review concerns about timestamp-based keying):**
The shared state key is NOT based on wall-clock time. Instead, it uses a deterministic `event_id` derived from fields available in every hook's stdin payload:
- PostToolUse: `event_id = session_id + "-" + tool_name + "-" + crypto.createHash('md5').update(tool_input_json).digest('hex').slice(0,8)`
- Stop: `event_id = session_id + "-stop-" + crypto.createHash('md5').update(content.slice(0,200)).digest('hex').slice(0,8)`

This ensures: (a) the same event_id is computable by any hook in the same chain for the same invocation, (b) no wall-clock timing dependency, (c) different tool invocations get different IDs even in the same second.

**State file location (addresses /tmp predictability concern):**
State files live in the PROJECT directory at `{cwd}/.planning/.hook-state/` (NOT /tmp). This directory is project-scoped, not world-readable, and co-located with the data it feeds. The `.hook-state/` prefix makes it clearly internal.

1. `buildEventId(data)` — Computes the deterministic event_id from the hook stdin `data` object. For PostToolUse: hashes `data.session_id + data.tool_name + JSON.stringify(data.tool_input || {})`. For Stop: hashes `data.session_id + "stop" + (data.content || "").slice(0, 200)`. Uses `crypto.createHash('md5')` (built-in, fast, no security requirement here — this is a correlation key, not a secret). Returns a string like `{session_id}-{event_hash_8chars}`.

2. `writeHookSignal(cwd, eventId, key, value)` — Computes path `{cwd}/.planning/.hook-state/{eventId}.json`. Creates `.hook-state/` dir if missing (`fs.mkdirSync({recursive:true})`). Reads existing file, merges `{[key]: value}`, writes back with `fs.writeFileSync`. On error: logs to stderr with `process.stderr.write('[hook-signal] write error: ' + err.message + '\n')` — does NOT silently swallow (addresses review concern about invisible failures). Still does not throw (non-blocking).

3. `readHookState(cwd, eventId)` — Reads the state file, returns parsed JSON. On error (file missing, parse error): logs to stderr and returns `{}`.

4. `cleanupHookState(cwd, eventId)` — Deletes the state file via `fs.unlinkSync`. On error: logs to stderr (file already gone = fine, other errors = warn). Also runs a stale cleanup pass: any `.json` file in `.hook-state/` older than 1 hour is deleted (addresses orphan state concern from review).

All four functions are synchronous. No async.
