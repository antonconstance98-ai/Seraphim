## What Was Built

### forge.md
Replaced the task-by-task sequential executor with a full GSD cycle for each build phase:

1. **Research** — spawns a fresh research subagent per build phase using `research-tracker.js`. The agent receives ONLY the build phase spec and tech stack context — no cumulative context from prior build phases (D-28: no context bleed).
2. **Discuss** — surfaces implementation details (not architecture) for human input. Skipped entirely in autonomous mode (D-32); auto-selected defaults are logged instead.
3. **Plan** — creates detailed task breakdown with file paths, implementation instructions, verify commands, and intra-phase dependencies.
4. **Execute** — uses `wave-planner.js resolveWaves()` to decompose tasks into dependency waves. Spawns separate agents per task within each wave. Waits for all tasks in a wave before starting the next (true parallelism within waves).
5. **Verify** — checks against success criteria from blueprint.md. On failure, presents human with retry/skip/abort options.

Each build phase result is appended to forge-log.md with a `SERAPHIM:FORGE_BUILD_PHASE` marker. The final `SERAPHIM:PHASE_COMPLETE` marker includes `build_phases_completed` and `build_phases_total` attributes.

### run.md
Replaced the 6-phase pipeline with a 7-phase pipeline and added three new mechanisms:

**7-phase sequence:**
`discover → envision → judge-vision → architect → judge-architecture → forge → crucible`

`judge-vision` and `judge-architecture` are the same `judge.md` command invoked with `--mode vision` and `--mode architecture` respectively.

**Autonomous lockout gate (D-30/D-31):**
- `--autonomous` flag blocks unless `vision.md` exists and contains `PHASE_COMPLETE phase="judge" mode="vision"` marker
- Exact refusal message: "Autonomous mode blocked. Discover and Envision need human input — without it you get a pure AI project. Use --skip-human-gates if you really want that."
- `--skip-human-gates` overrides the lockout with a loud WARNING printed to console

**Architect rework loop (D-35):**
- After `judge-architecture`, checks for `loop_required="true"` marker in output
- If found AND loop count < 1: calls `incrementLoop(projectRoot, phaseId, 'architect_judge')`, re-runs `architect` then `judge-architecture`
- If loop count >= 1: proceeds with current blueprint, logs cap reached message (max 1 rework)

**Updated output verification table:**
- `discovery.md` (single file, not old `discovery/external.md` + `internal.md` split)
- `architect-plans.md` (new from architect.md rewrite in 36.1-02)
- `blueprint.md` (produced by judge-architecture, not judgment.md)
- Removed `judgment.md` from table entirely
