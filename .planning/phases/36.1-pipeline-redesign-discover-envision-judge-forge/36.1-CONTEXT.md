# Phase 36.1: Pipeline Redesign — Discover, Envision, Judge, Forge - Context

**Gathered:** 2026-04-10
**Status:** Ready for planning

<domain>
## Phase Boundary

Redesign four wings of the Seraphim pipeline: Discover (broad→focused web research with real links), Envision (topic-by-topic discussion → alternative build plans), Judge (existing verdicts + new post-Judge human review gate), and Forge (GSD-style per-task research, sub-planning, wave execution, micro-verification). Add autonomous mode lockout gate enforcing human involvement through Envision.

</domain>

<decisions>
## Implementation Decisions

### Discover (Wing I) — Redesign
- **D-01:** Uses Perplexity + SearXNG for real web research. No fake or training-data-only URLs.
- **D-02:** Rounds are broad → focused, but no hard cap. Human can go deeper, pivot to a different topic, or rabbit-hole entirely. No fixed round limit.
- **D-03:** After each round, AI presents findings + explicit prompt: "Go deeper on a topic? / New direction? / I'm armed, move to Envision." Human always chooses.
- **D-04:** Interesting links accumulate across rounds. At the end, AI + human collaboratively filter to the final 5-7 high-importance links (articles, Twitter threads, YouTube, podcasts, docs).
- **D-05:** Bad search results: AI auto-retries once with refined query. If still poor, surfaces the issue and asks human for direction.
- **D-06:** Final output: `discovery.md` with research findings + curated 5-7 links. This arms the human for Envision.

### Envision (Wing II) — Redesign
- **D-07:** AI analyzes project scope and proposes 6-10 discussion topics (e.g., naming, target user, core loop, UX feel, visual identity, data/content, constraints). Human reorders, adds, or removes topics before discussion starts.
- **D-08:** Each topic is discussed conversationally. After each topic, AI evaluates whether there's enough context to draft build plans. When threshold is hit, offers to start drafting.
- **D-09:** AI generates 2-4 alternative build plans based on complexity (AI decides count: simple=2, medium=3, complex=4). Plans cover conceptual design, structure, UX/UI, and non-technical aspects.
- **D-10:** All alternative plans pass to Judge for stress-testing.

### Judge (Wing III) — Extension
- **D-11:** Judge stress-tests each alternative plan as before (SURVIVES / FATAL_FLAW / CONDITIONAL). No change to core judge logic.
- **D-12:** NEW: After Judge writes verdicts, pipeline pauses for human review. Human has full power: can kill surviving plans, merge ideas from multiple plans, add priority notes for Architect.
- **D-13:** Human review is appended to `judgment.md` as a `## Human Review` section. Architect must read this section — it's not optional.
- **D-14:** If autonomous mode is on, this gate is skipped (but autonomous can only be on after Envision — see D-15).

### Autonomous Mode Lockout
- **D-15:** Autonomous mode cannot be enabled until Envision is complete. If attempted before, pipeline refuses with blunt message: "Autonomous mode blocked. Discover and Envision need human input — without it you get a pure AI project. Use --skip-human-gates if you really want that."
- **D-16:** Override available via `--skip-human-gates` flag. Produces loud warning but allows it. This is an explicit opt-in to pure AI, not an accident.

### Forge (Wing V) — Reinforcement
- **D-17:** Forge uses GSD-style execution internally: per-task research before implementation (not assumptions), sub-planning with concrete tasks and acceptance criteria, wave-based parallel execution with dependency resolution, micro-verification after each wave/task.
- **D-18:** Forge reads the build plan that survived Judge + human review. It does NOT re-decide architecture — it executes what was decided.

### Claude's Discretion
- Internal prompt structures for each wing's subagent dispatch
- Search query construction for Perplexity/SearXNG
- Discussion topic generation heuristics
- Complexity assessment for plan count (2-4)
- Forge wave decomposition strategy

</decisions>

<specifics>
## Specific Ideas

- The 5-7 links should be diverse sources: not all articles, mix in Twitter threads, YouTube videos, podcasts, docs
- Discussion topics in Envision should feel like a founder/builder brainstorm, not an interview
- The post-Judge human review should feel empowering — "here's what survived, what do YOU want to do with it?"
- The autonomous lockout message should be genuinely opinionated, not corporate-polite
