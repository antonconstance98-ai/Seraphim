# Phase 36.1 Plan 02: Judge and Architect Rewrite Summary

Two command files rewritten for the two-pass pipeline. Judge now has distinct behaviors per `--mode` flag. Architect now generates multiple technical plans from vision.md instead of a single blueprint from judgment.md.

## What Was Built

### Task 1: judge.md — Two-pass with --mode flag

judge.md now supports two completely different behaviors:

**`--mode vision` (Pass 1 — Light Collaborative Review)**
- Reads vision.md
- Reviews with a collaborative, advisory tone — "have you considered..." not "this will fail"
- Presents each suggested tweak individually to the human (approve/reject per tweak)
- Rewrites vision.md in-place with all approved tweaks applied
- Appends `SERAPHIM:PHASE_COMPLETE phase="judge" mode="vision" approved_tweaks="N" rejected_tweaks="N"` marker
- This marker is what run.md checks for the autonomous lockout (per D-30)

**`--mode architecture` (Pass 2 — Adversarial Architecture Stress-Test)**
- Reads architect-plans.md (aborts if missing with clear message)
- Parses SERAPHIM:PLAN markers via parseMarkers()
- Stress-tests each plan on four dimensions: feasibility, scalability, maintainability, risk
- Makes a verdict: winner (best plan), merged (synthesize multiple), or rework (all plans flawed)
- Writes blueprint.md with full precision spec (verdict winner/merged) OR rework-directive.md with loop_required signal
- Emits `SERAPHIM:PHASE_COMPLETE phase="judge" mode="architecture" verdict="..." loop_required="..."` marker

**Removed from old judge.md:**
- SURVIVES/FATAL_FLAW/CONDITIONAL verdict system (replaced by plan stress-test)
- judgment.md output file (replaced by blueprint.md / rework-directive.md)
- APPROACH marker parsing (replaced by PLAN marker parsing)

### Task 2: architect.md — Reads vision.md, produces N technical plans

architect.md now:

**Input changed:** reads vision.md (not judgment.md). Checks for Judge-approved PHASE_COMPLETE marker (mode="vision") — warns if absent but does not block.

**Rework pass support:** detects rework-directive.md from a previous Judge pass. If present, plans MUST address every constraint named in it.

**Complexity assessment:** AI evaluates vision and declares simple/medium/complex:
- Simple → 2 plans
- Medium → 3 plans (default)
- Complex → 4 plans

**Output changed:** writes architect-plans.md with SERAPHIM:PLAN/PLAN_COMPLETE markers (not blueprint.md, not APPROACH markers). Validates minimum 2 plans before accepting output.

**Removed from old architect.md:**
- judgment.md prerequisite check
- Blueprint writing (moved to Judge Pass 2)
- APPROACH/BLUEPRINT/TASK marker templates
