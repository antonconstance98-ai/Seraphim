3. **Add compression call after the warning message is built** (after the `message = ...` assignments around line 143, before the `output` object is constructed):

```javascript
// Phase 12 (D-05): Compress context when threshold exceeded
const compressThreshold = (minimaxConfig && typeof minimaxConfig.compress_context_pct === 'number')
  ? minimaxConfig.compress_context_pct
  : 60;

if (usedPct >= compressThreshold && minimaxConfig && minimaxConfig.enabled !== false) {
  try {
    const { compress } = require('/home/alucard/.claude/hooks/minimax-compress');
    // Compress a self-summarization prompt — the monitor does not have access to
    // conversation text, so we inject a directive for the agent to self-compress
    const summaryDirective = `CONTEXT COMPRESSION ACTIVE: You are at ${usedPct}% context usage. ` +
      'To preserve remaining context, mentally summarize what you know so far and ' +
      'work from that summary. Focus on: decisions made, current task state, ' +
      'files modified, and next steps. Drop verbose tool outputs from memory.';
    message += '\n\n' + summaryDirective;
  } catch (_) {
    // Fail-silent — compression directive is advisory, never blocks the warning
  }
}
```

**Design decision (Claude's Discretion — context text availability):** The monitor reads usage metrics from the bridge file but does NOT have access to the actual conversation text. Per research Open Question 1, the monitor cannot literally compress earlier conversation. Instead, inject a self-summarization directive when the threshold is hit, prompting the agent to mentally compress its own context. This is the pragmatic approach — no additional MiniMax API call needed, zero cost, and immediately effective.

**Important constraints:**
- The `async` keyword on the callback is safe — Node.js `on('end')` handlers accept async functions; any unhandled rejection is caught by the existing outer try/catch
- Do NOT move or alter the existing warning message logic — the compression directive appends to `message`, not replaces it
- Do NOT change the debounce logic, thresholds, or any other existing behavior
- The `require()` of minimax-compress is lazy (inside the conditional) — zero overhead when compression threshold is not hit (hot path unchanged)
- Bump the version comment at top of file: `gsd-hook-version: 1.31.0`
