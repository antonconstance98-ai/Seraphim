## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, pill padding, dot indicators |
| sm | 8px | Intra-card spacing, label-to-value gaps |
| md | 16px | Default padding inside cards and panels |
| lg | 24px | Between panel sections |
| xl | 32px | Between top-level dashboard panels |
| 2xl | 48px | Page-level vertical rhythm |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Touch targets for interactive tree expand/collapse nodes: minimum 44px tall (accessibility requirement)
- Progress bar height: 6px (1.5 Tailwind units) — matches existing `h-1.5` pattern in MilestoneProgressBar

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #0d0d0d | Page background, panel backgrounds |
| Secondary (30%) | rgba(255,255,255,0.05) — `bg-white/5` | Card surfaces, tree node rows, section containers |
| Accent (10%) | rgb(99, 102, 241) — indigo-500 | Reserved elements listed below |
| Muted text | #6b7280 — gray-500 | Secondary labels, empty state body text, axis ticks |
| Surface border | rgba(255,255,255,0.10) — `bg-white/10` or `border-white/10` | Card borders, dividers, incomplete progress track |
| Destructive | #ef4444 — red-500 | Failed UAT items, blocked validation status only |
| Success | #22c55e — green-500 | Passed verification items, 100% complete indicators |
| Warning | #f59e0b — amber-500 | REQUIRES_HUMAN_JUDGMENT badges, pending UAT items |

Accent (indigo-500) reserved for:
- Active/filled progress bars (phase completion bars, milestone bars)
- Chart.js line stroke in velocity chart
- Currently-active tree node highlight
- Primary CTA button background
- Wave completion dot indicators (filled state)

Accent is NOT used for: hover states on non-interactive rows, headings, or body text.

## Component Inventory

New components required for Phase 37:

### Dashboard Panels (Next.js server/client components)

| Component | File | Type | Data Source |
|-----------|------|------|-------------|
| `PhaseProgressPanel` | `components/PhaseProgressPanel.tsx` | Server | `.planning/` filesystem API route |
| `VelocityChart` | `components/VelocityChart.tsx` | Client (`'use client'`) | git log API route, Chart.js line |
| `RoadmapTree` | `components/RoadmapTree.tsx` | Client (`'use client'`) | ROADMAP.md + plan files API route |
| `WaveProgressPanel` | `components/WaveProgressPanel.tsx` | Server | `.planning/phases/` filesystem API route |

### Interaction Contracts

**PhaseProgressPanel:**
- Renders one progress bar per phase using `bg-indigo-500 h-1.5 rounded-full` — identical pattern to existing `MilestoneProgressBar`
- Shows: phase name (truncated at 60% width), completion percent right-aligned, plan count subscript
- No interactivity — display only

**VelocityChart:**
- Chart.js line chart, `type: 'line'`, responsive: true, 100% container width, height: 120px
- Dataset: borderColor `rgb(99, 102, 241)`, borderWidth 1.5, pointRadius 2, tension 0.4
- X-axis: visible, date labels, `text-xs` tick font, color `#6b7280`
- Y-axis: visible, commits/day, same tick style
- No legend
- Dynamic import inside `useEffect` — matches existing CostSparkline pattern exactly

**RoadmapTree:**
- Hierarchical: milestone > phase > wave > task > cost
- Expand/collapse per node via local `useState` — no external state manager
- Default state: milestone expanded, phases collapsed
- Expand button: `w-4 h-4` chevron SVG, rotates 90deg on expand via `transition-transform`
- Row hover: `hover:bg-white/5` — single-step surface lift only
- Cost column: right-aligned, `text-xs text-gray-500`, format `$0.0000`
- Keyboard accessible: each row is a `<button>` or uses `role="treeitem"` with `tabIndex`

**WaveProgressPanel:**
- One card per wave, showing: wave number, plan count, completion dot row
- Dot row: `w-1.5 h-1.5 rounded-full` — `bg-indigo-500` for complete, `bg-white/20` for incomplete — matches PipelineProgress pattern
- Agent count shown as `text-xs text-gray-500` subscript below plan count

## Interaction States

Every interactive element must implement all four states:

| State | Visual treatment |
|-------|-----------------|
| Default | As specified in color/typography sections |
| Hover | `hover:bg-white/5` surface lift — no color change on text or accent |
| Focus | `focus-visible:outline focus-visible:outline-2 focus-visible:outline-indigo-500 focus-visible:outline-offset-2` |
| Disabled | `opacity-40 cursor-not-allowed` — only applies if data is loading |

Loading state: Skeleton bars using `animate-pulse bg-white/10 rounded` at the same height as the content they replace. No spinners.

## Accessibility

- All progress bars: `role="progressbar"` with `aria-valuenow`, `aria-valuemin={0}`, `aria-valuemax={100}` — matches existing MilestoneProgressBar pattern
- Chart canvas: `aria-hidden="true"` with a sibling `<p className="sr-only">` describing the trend in text — matches existing CostSparkline pattern
- Tree nodes: `role="treeitem"`, `aria-expanded` on expandable rows
- Status badges (passed/failed/pending): use `role="status"` or `aria-label` describing the full state
- Color is never the sole indicator — all status states have a text label alongside any color dot
