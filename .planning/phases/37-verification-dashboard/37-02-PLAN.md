**audit-milestone.md** (per D-08):
- Frontmatter: `description: "Cross-phase milestone integration audit"`, `argument-hint: ""`, `allowed-tools: ["Read", "Write", "Bash"]`
- No arguments required — audits the current active milestone
- Step 1: Read `.planning/ROADMAP.md` to identify all phases in the current milestone. Extract phase slugs from `### Phase N:` headers
- Step 2: For each phase, read `.planning/phases/{slug}/*-VERIFICATION.md`. Collect all verification results. Display the `verified:` timestamp from each VERIFICATION.md frontmatter (per Pitfall 6). - Step 3: Read `.planning/REQUIREMENTS.md`. Count `[x]` vs `[ ]` markers to compute requirements coverage percentage
- Step 4: Spawn an integration-checker subagent with instructions:
  - "You are an integration checker. Read all VERIFICATION.md files provided. Check for: (1) cross-phase data contract consistency — do types/interfaces used in later phases match what earlier phases created? (2) requirement coverage — are all REQ-IDs from REQUIREMENTS.md covered by at least one plan? (3) key_link integrity — do cross-phase links (e.g., API route used by dashboard component) actually connect?"
  - "Flag any VERIFICATION.md with a `verified:` timestamp older than the latest commit to that phase's files — these need re-verification."
- Step 5: Write report to `.planning/audit-milestone-{YYYY-MM-DD}.md` using atomic tmp+renameSync. Format:
  ```
  ---
  milestone: {milestone name}
  audited: {ISO timestamp}
  phases_audited: N
  coverage: N%
  stale_verifications: N
  cross_phase_issues: N
  ---
  ## Requirements Coverage
  {coverage % and list of uncovered REQ-IDs}
  ## Stale Verifications
  {phases where VERIFICATION.md is older than latest commit}
  ## Cross-Phase Integration
  {issues found by integration-checker}
  ```

**stats.md** (per D-10):
- Frontmatter: `description: "Terminal project statistics summary"`, `argument-hint: ""`, `allowed-tools: ["Read", "Bash"]`
- This is a READ-ONLY command
- Step 1: Read `.planning/ROADMAP.md`. Count total phases, completed phases (from Progress Table or by checking for completion markers)
- Step 2: Count total plans across all phases: `ls .planning/phases/*/*-PLAN.md 2>/dev/null | wc -l`
- Step 3: Count completed plans: `ls .planning/phases/*/*-SUMMARY.md 2>/dev/null | wc -l`
- Step 4: Read `.planning/REQUIREMENTS.md`. Count total requirements and completed requirements using `[x]` vs `[ ]` markers. Compute coverage percentage
- Step 5: Run git metrics:
  - Total commits: `git rev-list --count HEAD`
  - Files changed in milestone: `git log --oneline --since="$(git log --format=%aI --diff-filter=A -- .planning/ROADMAP.md | tail -1)" --stat | grep "files changed" | tail -1` (or simpler: `git diff --stat $(git log --format=%H --diff-filter=A -- .planning/ROADMAP.md | tail -1)..HEAD | tail -1`)
  - Days elapsed: compute from first commit in milestone to today
  - Average days per phase: days elapsed / completed phases
- Step 6: Display formatted terminal output:
  ```
  === Project Statistics ===

  Milestone: {name}
  Phases:    {completed}/{total} complete
  Plans:     {completed}/{total} complete
  Coverage:  {N}% requirements verified ({done}/{total})

  Git Metrics:
    Commits:       {N}
    Files changed: {N}
    Days elapsed:  {N}
    Avg days/phase: {N}

  Timeline:
    Started:  {date}
    Current:  {today}
  ```
- If no git history found, show: "No git history found. Commit your first change to see metrics."
